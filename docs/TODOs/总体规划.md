# Vulkan-Based Cross-Platform Game Engine Development Roadmap | 基于 Vulkan 的跨平台游戏引擎开发阶段规划

以下是一个**务实、渐进、可执行**的 6 阶段开发路线图，专为使用 **Vulkan 作为唯一图形后端**（通过抽象层支持 macOS/iOS）的跨平台游戏引擎设计。总周期建议 **6–12 个月**（视每周投入时间而定）。

> 📌 核心原则：  
> - **先跑通，再优化**  
> - **每阶段产出可运行 Demo**  
> - **严格隔离平台相关代码**

---

## 🔹 阶段 0：环境与基础准备（1–2 周）

### 目标

搭建稳定、可调试的 Vulkan 开发环境，验证跨平台编译能力。

### 任务清单
- [ ] 安装 **LunarG Vulkan SDK**（Windows / Linux / macOS）
- [ ] 配置 **CMake + 编译器**（MSVC / GCC / Clang）
- [ ] 在三平台（Win / Linux / macOS）成功编译并运行 `vulkaninfo`
- [ ] 创建 CMake 项目模板，支持：
  - 自动查找 Vulkan
  - 条件编译（`#ifdef VK_USE_PLATFORM_WIN32_KHR` 等）
- [ ] 集成 **GLFW**（用于窗口/输入）或 **SDL2**
- [ ] 启用 **Validation Layers**（调试必备）

> ✅ 交付物：`hello_vulkan` —— 能在三平台创建 Vulkan 实例并列出 GPU。

---

## 🔹 阶段 1：最小可运行渲染器（4–6 周）

### 目标
实现一个能渲染带纹理、光照的静态 3D 模型的 Vulkan 渲染核心。

### 关键模块
- [ ] Vulkan 实例 & 设备初始化（含交换链）
- [ ] 渲染管线（Graphics Pipeline）封装
- [ ] 命令缓冲区 & 提交队列管理
- [ ] 基础着色器（Vertex + Fragment，使用 GLSL → SPIR-V）
- [ ] 模型加载（使用 **tinyobjloader** 或 **Assimp**）
- [ ] 纹理加载（**stb_image** + VkImage/VkImageView）
- [ ] Uniform Buffer / Descriptor Set 管理
- [ ] 简单 Phong 或 PBR 光照模型

### 跨平台注意
- 使用 `VK_KHR_surface` + 平台特定扩展（`VK_KHR_win32_surface`, `VK_MVK_macos_surface` via MoltenVK, `VK_KHR_xcb_surface`）
- 在 macOS 上集成 **MoltenVK**（作为动态库或静态链接）

> ✅ 交付物：`static_scene_demo` —— 渲染一个旋转的带纹理立方体或模型（如 Suzanne），支持 Win/Linux/macOS。

---

## 🔹 阶段 2：引擎核心架构搭建（4–8 周）

### 目标
构建可扩展、模块化的引擎骨架。

### 子系统设计
- [ ] **资源管理器**（Resource Manager）  
  - 缓存纹理、网格、着色器
  - 异步加载（可选）
- [ ] **场景图 / ECS**  
  - Entity-Component-System（推荐）
  - Transform、MeshRenderer、Camera 组件
- [ ] **相机系统**  
  - 透视/正交投影
  - FPS / Orbit 控制
- [ ] **输入系统抽象**（基于 GLFW/SDL2 封装）
- [ ] **日志 & 断言系统**
- [ ] **数学库集成**（GLM）

> ✅ 交付物：`engine_sandbox` —— 可动态添加/删除实体，控制相机，加载多个模型。

---

## 🔹 阶段 3：高级渲染功能（6–10 周）

### 目标
提升画质与性能，接近现代引擎基础能力。

### 功能列表
- [ ] **帧缓冲 & Render Pass 抽象**
- [ ] **深度测试、混合、面剔除** 正确配置
- [ ] **多 Pass 渲染**（例如：几何 Pass + 光照 Pass）
- [ ] **UBO/SSBO 优化**（合并、对齐）
- [ ] **Descriptor Pool / Allocator 优化**（避免每帧重建）
- [ ] **简单阴影映射**（Shadow Mapping）
- [ ] **HDR + Tone Mapping**
- [ ] **基本抗锯齿**（MSAA 或 FXAA）

> ✅ 交付物：`advanced_rendering_demo` —— 包含阴影、PBR 材质、多光源场景。

---

## 🔹 阶段 4：工具链与编辑器雏形（4–6 周）

### 目标
提升开发效率，支持可视化调试。

### 工具集成
- [ ] **ImGui 集成**（用于调试 UI 和简易编辑器）
- [ ] 实时查看：
  - FPS、GPU 时间
  - 实体列表、组件属性
  - 资源使用情况
- [ ] **RenderDoc 集成**（帧捕获调试）
- [ ] 热重载着色器（监听 `.spv` 文件变化）

> ✅ 交付物：`editor_prototype` —— 带 ImGui 面板的游戏窗口，可调整光源参数、切换模型。

---

## 🔹 阶段 5：跨平台扩展与优化（持续进行）

### 移动端（Android）
- [ ] 使用 **Android NDK + CMake**
- [ ] Vulkan on Android（ANativeWindow）
- [ ] 触摸输入映射
- [ ] 性能优化（降低分辨率、简化着色器）

### Web（可选，高难度）
- [ ] 通过 **Emscripten** 编译 C++ → WebAssembly
- [ ] 使用 **WebGPU 后端替代 Vulkan**（需抽象图形 API）
- ⚠️ 注意：**Vulkan 无法直接在浏览器运行**，必须重写图形后端为 WebGPU

### macOS/iOS
- [ ] 确保 **MoltenVK** 正确打包到 App Bundle
- [ ] Metal 性能调优（MoltenVK 有开销）

## 🛠️ 关键技术栈汇总

| 类别 | 推荐方案 |
|------|--------|
| 图形 API | Vulkan（+ MoltenVK for Apple） |
| 窗口/输入 | GLFW（轻量）或 SDL2（功能全） |
| 数学 | GLM |
| 模型加载 | tinyobjloader（简单） / Assimp（复杂格式） |
| 纹理 | stb_image |
| 调试 UI | Dear ImGui |
| 构建 | CMake + vcpkg |
| 包管理 | vcpkg（官方支持 Vulkan / MoltenVK） |
| 调试工具 | RenderDoc, vkconfig, GAPID（Android） |

---

## ⚠️ 重要提醒

1. **不要过早优化**：先让三角形动起来，再考虑每帧 0.1ms 的开销。
2. **Validation Layers 是你最好的朋友**：开启 `VK_LAYER_KHRONOS_validation`。
3. **macOS 不是原生 Vulkan**：MoltenVK 有性能损失和兼容性限制，测试必须覆盖。
4. **抽象要克制**：初期可接受少量 `#ifdef`，等模式稳定后再重构为接口。
